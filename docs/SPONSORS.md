# Sponsor tools: what we actually use

Status is stated as of the last verified build. Update this file if it changes. Do not claim a tool on Devpost that is marked "not used".

| Sponsor | Status | How it is used / what to do |
|---|---|---|
| **PayPal** (required) | Used | OAuth, Transaction Search (31-day chunking), Invoicing v2 create/send/remind/get/list, webhook signature verification. Verified against a mocked HTTP layer in CI; live sandbox verification is done with `python backend/scripts/doctor.py`. |
| **AG Grid** | Used | **AG Grid Community 36.3** powers the Transactions page (infinite row model: server-side paging, sorting, filtering, search; column visibility; CSV export; detail panel). **AG Studio 3.1** powers the Analytics Studio page: a seeded dashboard (KPIs, revenue by month, status donut, revenue by customer, transactions grid) that users can edit, rearrange and cross-filter. **Studio Agent Framework:** Studio's own built-in agents (lead, page and widget agents) run on **Gemini through our backend** via a custom model adapter (`frontend/src/lib/studioAdapter.ts` -> `POST /ai/studio-turn`), so the key never reaches the browser and the payload is size-limited. AG Studio is a commercial product: it runs without a licence but shows a watermark and a console banner. The free 45-day trial key is self-serve from AG Grid's licence page (https://www.ag-grid.com/studio/license-pricing/); set it as `NEXT_PUBLIC_AG_LICENSE_KEY`. **Polish the brief rewards:** a **custom widget** ("Who owes what" scoreboard, `OwesScoreboard.tsx`, fed through Studio's `context`), a **PayPilot theme** (`studioTheme.withParams`), and **custom agent tools** on Studio's lead agent (`list_overdue_invoices`, `queue_payment_reminder`) that queue reminders for human approval. Not done: custom tool-call renderers in the chat panel, and a fully custom agent team. |
| **Render** | Used once deployed and a run is seen | Web service + Postgres + **Render Workflows** (`workflow_main.py`: `sweep_account`, `sweep_all` fan-out, one instance per account, retries) + a cron job that triggers the nightly sweep, all in `render.yaml`. The sweep prepares reminders for approval; nothing is sent. Claim the sponsor credits (link in `docs/DEPLOY.md`). Do **not** claim Workflows until a real run succeeded in the Render dashboard; demo-simulator users run the sweep inline instead. |
| **APIMatic** | **Not used** | The Context Plugin is a *development-time* aid for AI coding assistants. It is not a runtime dependency, so nothing in this repo can show it. To qualify you would install it in your coding assistant, use it to review `backend/app/services/paypal.py` against PayPal's API spec, and describe what it caught. Only claim it if you did. |
| **Bryntum, Channel3, Zapier, Elastic, Postman, others** | Not used | Not relevant to this product. |
| PayPal Agent Toolkit (MCP) | Not used | TypeScript/MCP. We call the same invoice REST endpoints directly from Python, behind our own approval gate. |
